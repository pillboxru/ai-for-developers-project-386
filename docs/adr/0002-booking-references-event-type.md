# Бронирование ссылается на тип события и не копирует его длительность

Бронирование хранит только начало и ссылку на тип события, а конец вычисляется как начало плюс длительность типа. Поэтому длительность типа, а также сам тип нельзя менять или удалять, пока есть хотя бы одно его бронирование, включая прошедшие: иначе задним числом изменятся уже назначенные и прошедшие встречи. Чтобы предложить другую длительность, владелец создаёт новый тип события.

## Considered Options

- **Копировать длительность в бронирование.** Тогда тип можно свободно редактировать, но у бронирования появляется вторая длительность, которая может разойтись с типом. Отвергнуто: у встречи должен быть один источник длительности, иначе бронирование и тип могут разойтись.
